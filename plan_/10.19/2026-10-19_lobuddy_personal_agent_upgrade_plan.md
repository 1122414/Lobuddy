## 1. 下一目标

让 Lobuddy 成为一个长期与你相处、理解近况，并能在明确授权内持续照看事情的桌面个人代理。

本轮围绕两个可体验的结果实施：

1. **相处能接续**：她知道最近在聊什么、哪些话题暂时不提、你希望怎样被回应；跨会话接上真实经历，不机械引用记忆或连续追问。
2. **托付不会丢**：你明确交代的事有独立状态、时间、等待条件和结果；切换聊天或重启后仍可查看、暂停、取消和安全继续。

保留浊蒂外形、当前选定声音和既有主要能力。性格随相处形成，明确偏好优先于五维数值；不预设恋爱关系或固定人物背景。

### 核心验收故事

你说：“这个项目先放一放，周五晚上提醒我接着看，回来时帮我找出上次的决定。”

- 时间不明确时只补问必要信息；“周五晚上”不能静默绑定一个用户不知道的时间。
- 确认后保存提醒时间、项目关联和授权范围，展示可撤销的委托卡。
- 换会话或重启后，该委托与项目决定仍然存在。
- 到时默认只冒气泡；你说“今天不想聊工作”，立即安静，不自行编造新的提醒日期。
- 电脑睡眠或应用退出时不承诺照常执行；恢复后按明确的逾期策略处理，并显示实际延迟。
- 下次回来时，给出有来源的决定、未完事项和可选下一步；只有你授权后才继续执行有副作用的动作。

此场景不是后台永久运行大模型，而是持久状态配合有界事件调度。

## 4. 本轮范围与默认决策

### 运行边界

- 首发仍为 macOS Apple Silicon。本轮先采用 Electron 托盘常驻 + Python 服务，不新增云端常驻、系统守护进程、开机自启或手机端。
- 关闭管理/聊天窗口不等于退出；明确退出应用停止执行与采音。退出提示未结束委托数量，默认安全停止，不通过阻止退出强迫常驻。
- 系统睡眠期间暂停执行；唤醒后重新读取时间、授权和任务状态。不能承诺关机期间提醒。
- 常驻轮询不调用模型。模型只处理有来源、有预算的具体工作；空闲不自动制造任务。
- 保留一个前台对话与一个后台执行槽，前台聊天和语音优先。

### 托付与陪伴边界

- 只将用户明确交代的事项转成可执行委托。普通愿望、引用、假设和情绪表达不自动创建任务。
- 陪伴邀请、明确提醒、任务结果通知分别记录原因和投递状态；后两类不占闲聊次数，但仍遵守安静与静音规则。
- 专注或免打扰时通知进入收件箱，默认不发声、不抢焦点；解除后合并提示一次，不逐条轰炸。用户可为具体提醒显式设置例外。
- “今天不聊工作”形成到本地当日结束的交流边界，不擅自取消已授权后台任务；“停一下这个任务”才暂停对应委托。语义不明确时询问目标对象。
- 保留每日闲聊 3 次、间隔 60 分钟、忽略冷却 120 分钟和主题 7 天去重。明确反馈优先。

### 信息和自修改边界

- 优先做选中文本/粘贴、文件选择、链接提交；不后台监听剪贴板，不默认读屏、扫描磁盘或读取 Codex 会话。
- 邮箱、日历、GitHub/Codex 深度连接和远程事件订阅列为后续扩展，不作为本轮完成条件。
- 不自动长期保存临时情绪；明确要求保留的近况记录有来源、用途和到期时间，敏感内容继承确认规则。
- 继续禁止任意代码执行、自改应用源码、修改评测答案、扩权限和更换声音。模型提议本身不构成授权。
- 优先复用已有依赖；本地时间使用标准库 `zoneinfo`，不为本轮引入分布式调度平台或新的数据库。

## 5. 委托、调度与安全续行

### 5.1 对象与状态

新增业务对象由 Python/Pydantic 定义，SQLite 为权威来源。下面是拟定契约，不表示已有表或接口。

| 对象 | 必要内容 | 与现有实现关系 |
|---|---|---|
| Delegation 委托 | ID、目标、类型、项目、来源、范围、验收条件、授权、预算、状态、版本 | 一个委托可关联多个现有 task/turn/session，不替换旧 ID |
| Run 一次执行 | 委托 ID、触发 ID、固定工作流版本、当前步骤、执行状态、验收结果 | 接入现有队列、OutcomeRepository 与结算机制 |
| Wait 等待条件 | 时间/应用事件/用户反馈、有效期、已消费位置、解除原因 | 不以一段聊天摘要代替可调度状态 |
| Checkpoint 检查点 | 已完成只读节点结果、来源版本、必要输入、后续节点、写操作状态 | 明确哪些内容可复用；不能由它单独证明副作用未发生 |
| Notification 通知 | 原因、来源、关联委托、到期时间、投递/展示/确认状态 | 宠物气泡和管理收件箱是同一通知的视图 |

委托状态使用 `draft / scheduled / ready / running / waiting_user / waiting_event / paused / completed / cancelled / failed / needs_review`；暂停不等于失败。每次执行继续分开记录运行状态和 `verified / failed / unknown` 结果。

- 目标更改、取消、重新授权增加委托版本；执行前和产生副作用前检查版本，旧事件不能复活旧目标。
- 完成业务结果后才设置 completed；等待确认不伪装成完成。
- 提醒的完成条件是按约定持久化通知并满足投递条件；“已提醒”和“用户已读”分别展示，绝不根据模型输出推断用户看到了。
- 窗口刷新或重复请求不重复创建委托；复用既有请求 ID，并对触发 ID、通知 ID、结算 ID 建唯一约束。

### 5.2 首批触发方式

1. 一次性指定时间提醒。
2. 明确授权的每日或每周固定时间提醒，可设结束日期；先不开放任意 cron 字符串。
3. 有来源的内部事件：用户返回应用、专注结束、指定委托完成、用户明确选择继续。

提醒只靠确定性调度即可完成，不必调用模型。若还要求到时生成项目回顾，则将生成作为独立、受预算约束的执行步骤；模型失败时仍投递原提醒，说明回顾暂不可用。

时间默认沿用应用配置时区，首次展示明确时区（未配置时提议使用 `Asia/Shanghai`）。一次性时间保存 UTC 瞬间和原时区；周期任务保存本地时间规则与时区。系统时区改变不静默改变既有安排；夏令时不存在或重复时刻按明确策略处理并测试。

**建议默认逾期规则：**一次提醒延迟不超过 24 小时，恢复后提示一次且标注延迟；超过 24 小时进入“已错过”列表，不弹出催促。周期任务漏过多个周期只保留一次汇总，后续从下一个合法时刻继续；可在具体委托中配置或关闭补提醒。涉及文件写入的逾期任务不自动补跑，转 needs_review。

调度器单实例领取任务，持久化执行所有者与期限；防止两个 Electron 实例重复启动服务。恢复领取权不等于获得重放外部动作的许可。

### 5.3 恢复规则

- 只读计算：授权仍有效、输入版本一致、预算足够时可从检查点继续。
- 已确认完成的写操作：加载证据，跳过动作，不重做。
- 写操作开始后状态未知：转 needs_review，核对真实产物；无法核实则等待用户处理。
- 尚未执行的写操作：重新校验范围和原审批有效性；输入、预览、目标、工作流版本变化则重新审批。
- 用户取消时停止后续调度和生成；已经发生的外部副作用不伪装为已撤销。
- 复用既有 ToolPolicy、Guardrails、预算与 HITL。持久授权只允许指定目的、范围和期限，不建立“永远允许所有工具”。

### 5.4 成本与资源

新增后台话题、摘要、经验评测仍共享现有每日 30 调用、60000 输入 token、8000 输出 token 上限，调用前预留，重启不清零。

用户显式派发的任务单独计量；无人值守续行除单任务预算外，再受每日自动执行硬上限约束。首版建议与学习合计共享上述后台总上限，避免开两套默认额度使费用翻倍；前台手动继续独立计费并可见。不得因改任务名称逃避计量。

所有执行有超时、有限重试与明确错误分类；不在后台无界运行。无预算、离线或凭据失效时保留等待状态，前台普通功能和确定性提醒仍可使用。

## 6. 近况理解与自然陪伴

### 6.1 四类信息分开管理

| 信息 | 保存与使用规则 |
|---|---|
| 稳定偏好 | 复用关系记忆；用户纠正优先，可查看、修改、撤销和遗忘 |
| 当前交流状态 | 倾听/讨论/执行/安静及当前话题；默认仅会话有效，不自动变成性格事实 |
| 明确近况 | 只有授权的事实进入持久记录；保存来源、项目、有效期；到期停止注入，保留可管理历史而非自动永久删除 |
| 项目与委托 | 项目目标、来源材料、决定、未完事项、关联委托；任务状态通过业务仓库读取，不能从摘要猜测 |

项目关联不确定时保留未归类来源，不能凭同名词把两件事合并。时间变化、项目结束或用户纠正后，更新检索和摘要；不会继续把旧的“最近”当作当前状态。

新增分享入口：粘贴文本、选择文件、提交链接，并选择“只用于本次 / 加入指定项目”。保存必要摘录、来源标识、时间、内容摘要和校验值，不默认复制整个目录。文件已变更、删除或权限撤销时标记来源失效；外部链接继承 URL/重定向/大小检查。

遗忘时沿来源关系处理记忆、项目摘要、待处理学习与相关主动话题。执行账本只保留防止重复动作所必需的最小记录，并清除可删除的用户正文；涉及正在等待的委托时明确展示影响，不静默取消其他任务，也不从旧聊天再提取已遗忘事实。

### 6.2 主动话题生成

先由确定性策略决定是否允许主动，再从可靠来源选择话题意图，最后按预算生成短句。可选意图：延续未完交流、回应已分享的进展、专注结束后的轻关心、普通邀请。

- 输出必须带来源 ID；生成内容不能引入来源之外的具体经历、日期或人物事实。
- 不要求每次以问题结尾；“先听我讲”时允许短回应和沉默，不连续追问。
- 生成失败、无可靠来源或预算不足时使用普通短邀请或保持安静，不临时编造话题。
- 候选生成后、显示前再次校验来源、用户活动和话题边界，防止迟到气泡打断新的对话。
- 主题 ID 采用稳定记录与别名映射；先实现显式主题关联，语义同义识别作为有置信度的辅助，不能宣称完全识别所有同义表达。
- 用户否定某次表达时保存具体纠正及适用范围，不通过增加某个性格数值代替行为变化。

## 7. 可验证的方法学习

本轮先扩展一个已有场景：**同一项目的多来源资料归纳**。文件复制场景继续使用稳定流程，不在首轮自动改写有副作用的执行顺序。

### 学习输入与可改范围

- 从授权任务轨迹提取目标、实际调用、输入条件、验证结果、失败诊断及用户纠正，先脱敏再交给模型。
- 候选必须明确引用“哪个执行证据支持这个改动”，不能只挂一个来源 ID 而不使用其内容。
- 初始可调参数限定为已实现组件的来源去重策略、相关项目资料选择和摘要组织模板；每种参数单独声明可验证属性。
- 自动晋升首选可以确定性检验的优化，例如去除同一规范化来源的重复读取，同时保留原来源到证据的映射；不能为了少调用而遗漏不同来源。
- 涉及摘要含义、语气、事实重要性的修改保留待评审；不会将格式压缩或模型自评分当作语义改善的证明。

### 评测与投放

## 8. 界面、接口与数据迁移

### 界面

- 宠物层：状态、短气泡、通知原因；不增加常驻复杂控制条。
- 快速聊天：当前话题、关联项目、记忆轻提示、委托确认卡与原有语音开关。
- 管理窗口新增“托付给她的事”：正在处理、等待你、等待时间/事件、暂停、已完成/已取消；可查看来源、验收标准、授权、产物和执行记录。
- “最近与我们”：近期项目、未完话题、明确近况；每项可查看来源、纠正、到期和遗忘。
- “通知”：区分提醒、任务结果、陪伴邀请，显示计划时间和实际时间。
- “学习与进化”：展示实际采用的经验、候选差异、任务级评测、观察期与回退，避免把 EXP 展示成真实能力证明。

### 拟新增协议能力

继续 React → preload → Electron → Python stdio JSON-RPC；渲染层不直接拿凭据、Shell 或文件读取权限。新接口遵守现有命名与类型生成方式，以下按能力分组：

| 接口组 | 操作 |
|---|---|
| 委托 | 创建草稿、确认、查询、修改目标/时间、暂停、继续、取消、查看执行/证据 |
| 调度 | 查询下一触发、逾期状态、有效时区与策略；调度事件不由任意渲染消息伪造 |
| 项目与分享 | 创建项目、导入授权材料、关联/解除来源、读取近期回顾、来源失效/删除 |
| 话题与通知 | 读取、展示确认、已读、稍后、屏蔽、撤销；保持消息来源和原因 |
| 经验 | 查询采用记录、候选来源、任务级对照结果及回退 |

新事件关联 delegation_id、run_id、project_id（适用时）以及既有 session/task/turn/sequence。修改使用版本检查，重复投递使用事件 ID 去重；陈旧客户端不得覆盖新状态。

版本化迁移保留原宠物、会话、记忆、技能、任务 ID；新增映射，不批量把历史聊天任务自动转换成长期委托。真实迁移前备份数据库、资源和投影；合成库验证迁移两次一致、中断恢复及匹配版本的备份还原。旧程序不得直接写不兼容的新库。
