# Lobuddy 持续陪伴产品实施计划

目标来源：2026-10-28 用户要求持续实现终极产品、每阶段提交；优先自然主动陪伴，同时续接近况与带来符合兴趣的新鲜事。依据 [产品扫描](../reports/2026-10-28_product_state_and_evolution.md) 与 [五项目调研](../reports/2026-10-28_companion_projects_research.md)。起点：40b5008；既有 T10 未提交工作不纳入本计划提交。

## 完成定义

终局是长期相处的桌面伙伴：有来源地接续近况、带来相关新内容、自然交流、尊重边界，并通过明确反馈越来越适合用户；需要办事时能持续托付，成长与完成都有可检验证据。完成必须同时具备实现、回归、原生/真实模型证据与必要真人体验验收。仅完成下面某一阶段或通过工程测试，不代表终局达成。

## A1 实施选择与验收

情景记忆采用现有 SQLite 和标准分词，不新增向量库。候选在限制数量之前检查作用域、状态、有效期和遗忘屏障；按词项相关性排序。无实体指向的“后来呢”需由 A2 的明确话题上下文补齐，不能随机猜测旧事。

修正预算基数：memory_prompt_budget_percent 用于 memory_prompt_budget_chars 的情景召回份额（默认 4000×0.2=800 字），不再随当前问句长短归零；0 仍表示不注入情景记忆，整体上下文仍受既有上限约束。同步设置描述和预算测试，明确记录这一行为修正。超出预算的长候选不阻止后续能放下的短候选。

交流状态从明确的完整分句提取，允许常见礼貌词、时间和“就好”等尾语；仍拒绝引用、假设和疑问中的指令。临时不聊按现有当天边界到期，长期边界可在现有界面撤销；不取消已授权任务。

| 问题 | 目标检查 | 修改前 | 预期修改后 | 当前验证 |
|---|---|---|---|---|
| LS-02 | 保存星桥合成事实；输入关键词与自然短问句 | 前次探针观察均未进入情景上下文 | 两种问法取得相同有效证据 | 关键词及两种自然问法通过 |

## A2 实施选择与验收

新增 `companionship.accept`，由桌宠明确点击调用，以 notice_id 幂等。接入时再次检查展示有效期、来源版本和范围；同项目且空闲的会话可以复用，否则创建对应项目会话。原话以 assistant 消息保存，来源仅作不可信上下文，不作为用户指令。重复点击及重启返回原会话；来源更新、到期、遗忘或会话切换项目时撤销接话依据、派生记忆与引擎关联。

存储由 3 升至 4，新增接话与上下文使用记录。只允许已验证的 TS v3 迁移前缀升级，保留私有 SQLite 快照后事务升级；旧 Python v0–2 仍要求备份并导入新目录。原迁移校验值与冻结 RPC 行为保持不变。接话不将导航当作偏好学习。

## B 实施选择与验收

最多六个候选交错取自有效项目来源与全局相处记忆；同正文去重，不让一个来源类别占满。用户已经忽略/屏蔽或刚展示过的话题仍由原有规则排除。公共新鲜事的来源配置与发现留在 C，B 先完成共享选择机制。

选择器返回 speak/defer/pass。speak 生成一两句自然短话，必须包含选中材料里的精确片段；独立审查只看该材料与拟发送内容，拒绝新事实、擅自揣测、压力式追问和调试信息。审查是有界风险控制，不作为普遍事实正确性的证明。每次最多两次受控 DSH 分析，预留 16384 输入、2048 输出及 2 调用，仍使用当前共享日额度；宁可不发，不自动加预算。真实调用中，SDK 默认高推理模式在 1024、甚至 2048 输出仍出现截断；最终仅陪伴的两次调用显式请求 SDK 已支持的 reasoningEffort=off，单次输出保留 1024。其他任务的推理设置不变。选择输入按桥的 7000 字节上限裁减候选，审查不超过 5000 字节。

已正常结束的选题任务可原子退回尚未调用的审查份额；已经调用、失败或中断的请求不退回其调用份额。此行为仅为陪伴选题启用，其他学习任务保留原结算方式。默认 8000 输出日额度内，三次完整双调用最多占 6144；一次延期后完整重评占 3072。其他消费者会进一步占用额度，展示次数上限并不保证发满。保持此成本边界，不提高默认额度。

模型 defer 仅适用于五分钟内的 conversation_finished；运行时发现活动变化也可延期。当前事件有效期内最多延期五分钟重评一次；重评携带事件已经过去的秒数，避免把旧事件当作刚结束聊天。pass、空候选、调用失败和验证失败保持安静，不扣展示次数。后台候选携带来源版本和活动代次，发送前重查；前台输入、语音、专注和来源变化会阻止迟到的话。未展示的新格式结果不跨服务重启复用；A2 已接话的会话仍持久保存。

沿用 dialogue_invitation 表，增加版本化 JSON；旧精确引文格式继续有界读取，新生成均使用新格式。改进用户可见回复指令，默认使用项目/来源标题解释依据，避免 raw source_id 等内部细节；用户明确索要标识时仍可提供。

| 问题 | 目标检查 | 修改前 | 预期修改后 |
|---|---|---|---|
| LS-03/11 | 多来源、新旧、低价值、重复、空池 | 静态确认首个合格项和固定模板；空池也发通用邀请 | 有限比较；零发言是有效结果；无来源不凑数 |
| LS-03/11 | 编造来源、事实否定、材料内指令、未通过审查 | 旧精确引文能限制被引用部分，其他自然表达尚未实现 | 精确依据、独立审查与静态限制共同阻止不合格短句 |
| LS-03/11 | 前台抢占、延迟结果、重启、额度用尽与来源失效 | 旧等待与展示保护未覆盖新决策状态 | 未经当前有效性检查不展示；延期不无限重试 |
| LS-03/11 | 真实模型固定场景对照与保留场景 | A2 样本事实续接通过，但偏说明、带调试细节 | 事实与自然度分别记录，有真实输出和明确未通过项 |

B1 的机制验收已完成：最终根检查 296 项通过，真实生成/审查/气泡操作及长气泡接话通过一次。原布局在真实长文本下把关闭按钮挤出视口，已在原窗口尺寸内修复正文滚动和操作行。

依据真实失败拆分阶段以保留可独立复核的实现。原 B 的产品要求没有减少：整组模型样本曾达到 15/16，但后续两个项目近况正例均 pass/low_value，预期仍为 speak；原生接话的长度也不稳定。这些保留为 B2 必须解决的质量项，不能将工程通过或安全沉默当作自然主动陪伴完成。见 [B1 实现与 B2 未决证据](../reports/2026-10-28_b_natural_invitations.md)。

## C 实施边界与验收准备

用户已选择 AI 陪伴、开源项目与创作工具。C1 先支持最多三个公开 GitHub 项目的官方 Releases，通过公开 API 的 published_at 判断时效，默认不订阅；示例为 AIRI、N.E.K.O.、ComfyUI。此次已核对 AIRI 2026-10-29 与 ComfyUI 2026-10-27 的正式发布；N.E.K.O. 近期为预发布组件，不能充当近期正式应用版本。RSS/Atom 不属于 C1 必须范围，后续有实际来源需要时再增加，避免同时实现多个解析器。

沿用现有公共网络校验和 DNS 绑定，不跟踪整站、不抓取私人账户、不自动访问文章链接。文章来源保持独立于用户的共同经历与记忆。C1 仅配置、发现、查看和清除缓存；C2 才把资讯接入气泡与会话，并验证撤销和到期后的派生上下文。B2 的事实质量门槛仍未完成，不因先做 C1 而关闭问题。

每项保留来源、原文链接、发布时间或更新时间的区别、读取时间与有效期；缺少可验证时间的条目不作为“新鲜事”。持久化每来源间隔、全日来源读取尝试与失败退避，重启或手动刷新不能重置额度；六个读取尝试每次最多四个 HTTP 请求（含跳转校验），不等同于上游 API 额度。选题继续使用已有模型日预算。近况与资讯交错进入同一个有界候选池，所有资料均为不可信上下文。设置存入现有 app_settings 的严格版本化 JSON；缓存条数和正文总量有固定上限，不引入依赖或第二个 SQLite 写入方。
