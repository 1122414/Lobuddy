# Lobuddy 5.8 优先级最高：基础修复计划

制定日期：2026-05-08  
目标版本：5.8.x  
交付对象：opencode  
优先级：P0

## 1. 目标

解决最影响后续开发的地基问题：

- `app/main.py` 过重。
- SQLite schema 升级缺少版本化迁移。
- 仓库存在运行产物污染风险。
- 文档与中文字符串存在编码异常风险。
- `core/` 中部分模块直接依赖 Qt，测试和未来 headless 模式成本高。

## 2. 涉及模块

- `app/main.py`
- `app/bootstrap.py`
- `core/storage/db.py`
- `core/tasks/`
- `core/focus/`
- `core/events/`
- `ui/`
- `README.md`
- `TODO.md`
- `plan_/`
- `.gitignore`
- `tests/`

## 3. 任务优先级

### P0-A1：拆分 `app/main.py`

必须做：

- 新增轻量装配层，建议文件：
  - `app/container.py`
  - `app/ui_controller.py`
  - `app/service_wiring.py`
- `app/main.py` 只保留入口职责：
  - 创建 `QApplication`。
  - 调用 bootstrap。
  - 创建 container/controller。
  - 启动事件循环。
  - 处理顶层退出。
- 将以下逻辑移出 `app/main.py`：
  - MemoryService / MemoryWriteGateway 初始化。
  - SkillManager / SkillMaintenance 初始化。
  - HITL provider 装配。
  - FocusCompanion 装配。
  - TaskManager 与 UI 信号连接。
  - 主题应用。
  - idle timer 和宠物状态更新装配。

严禁做：

- 严禁在拆分时改变现有 UI 行为。
- 严禁移动业务逻辑到 `app/` 新文件中；`app/` 只允许 composition root。
- 严禁直接删除现有功能连接，必须通过测试或 smoke 保证行为保持。

验收标准：

- `python -m py_compile app/main.py app/container.py app/ui_controller.py app/service_wiring.py`
- 现有 UI 启动路径不变：`python -m app.main`
- 退出、任务提交、HITL、memory、skill、focus 的信号连接不丢失。
- `app/main.py` 行数显著下降，目标低于 250 行。

预留接口：

- `AppContainer.services`
- `AppContainer.ui`
- `UiController.start()`
- `UiController.shutdown()`
- `ServiceWiring.create_services(settings)`

### P0-A2：建立 SQLite 迁移体系

必须做：

- 在 `core/storage/db.py` 中引入 schema version 管理。
- 推荐使用 `PRAGMA user_version`，或单独 `schema_migrations` 表。
- 将现有建表逻辑保留为 bootstrap baseline。
- 新增可重复执行的 migration runner：
  - 从当前版本迁移到目标版本。
  - 每个 migration 可单独测试。
  - migration 失败时事务回滚。
- 将新增/已有表纳入版本意识：
  - `hitl_approval_log`
  - `skill_record`
  - `skill_event`
  - `skill_candidate`
  - memory tables
  - execution trace tables

严禁做：

- 严禁引入 Alembic 或 ORM。
- 严禁破坏现有数据库文件。
- 严禁在 migration 中清空用户数据。
- 严禁把 migration 写成只适配当前开发机数据库的脚本。

验收标准：

- 空数据库可初始化。
- 旧数据库可迁移。
- 重复运行 init/migrate 不产生错误。
- 测试覆盖 fresh init、idempotent init、user_version 升级、migration rollback。

预留接口：

- `Database.migrate()`
- `Database.get_schema_version()`
- `Database.set_schema_version(version)`
- `core/storage/migrations/`

### P0-A3：仓库卫生与运行产物隔离

必须做：

- 检查 `.gitignore`，确保忽略：
  - `__pycache__/`
  - `*.pyc`
  - `.pytest_cache/`
  - `.ruff_cache/`
  - `.coverage`
  - `logs/`
  - 本地数据库文件
  - 临时导出文件
- 检查当前已跟踪的 `.pyc` 或运行产物。
- 如发现已跟踪运行产物，给出清理计划；只有用户明确要求时才执行 git rm。

严禁做：

- 严禁删除用户数据目录。
- 严禁自动清空 `data/`、`workspace/`、`logs/`。
- 严禁在未确认的情况下改写 `.env`。

验收标准：

- `git status --short` 不再出现 pyc 运行产物变更。
- 可选新增 `scripts/check_repo_hygiene.py`。

预留接口：

- 后续接入 CI hygiene check。

### P0-A4：编码审计与文档修复

必须做：

- 审计以下文件是否为 UTF-8：
  - `README.md`
  - `TODO.md`
  - `plan_/design_plan/**/*.md`
  - `ui/*.py`
  - `core/**/*.py` 中的中文 UI 字符串。
- 修复明显乱码文本，优先修复用户可见文档和 UI 文案。
- 明确项目编码约定：所有文本文件使用 UTF-8。

严禁做：

- 严禁在不知道原文含义时猜测性重写历史计划内容。
- 严禁批量替换导致语义丢失。
- 严禁改动 `.env` 中用户真实配置。

验收标准：

- README 安装与运行说明可正常阅读。
- TODO 或旧计划若无法恢复原文，必须标注“历史编码损坏，保留归档”。
- 可选新增 `scripts/check_text_encoding.py`。

预留接口：

- 后续接入 CI encoding check。

### P0-A5：core/Qt 解耦起步

必须做：

- 不要求一次性移除所有 Qt 依赖。
- 先为任务、focus、progress 定义纯 Python 事件模型。
- UI 层通过 adapter 将 domain events 转换为 Qt Signal。
- 优先处理：
  - `core/tasks/task_manager.py`
  - `core/tasks/task_queue.py`
  - `core/focus/focus_companion.py`

严禁做：

- 严禁大规模重写 TaskManager。
- 严禁破坏现有 Qt Signal 调用方。
- 严禁删除现有测试 mock 支持。

验收标准：

- 现有测试继续通过。
- 新增最小测试证明 domain event 不依赖 PySide6。

预留接口：

- `core/events/domain_events.py`
- `ui/qt_event_bridge.py`
