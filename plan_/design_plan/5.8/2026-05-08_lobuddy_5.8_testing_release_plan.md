# Lobuddy 5.8 测试与发布计划

制定日期：2026-05-08  
目标版本：5.8.x  
交付对象：opencode  
优先级：P0

## 1. 目标

让 5.8 的架构演进可验证、可回归、可发布。

## 2. 涉及模块

- `.github/workflows/`
- `pyproject.toml`
- `tests/`
- `scripts/`
- `README.md`
- `app/health.py`

## 3. 任务优先级

### P0-F1：根项目 CI

必须做：

- 新增 GitHub Actions，至少包含：
  - `ruff check .`
  - `black --check .`
  - `python -m py_compile app core ui`
  - `pytest tests/`
- CI 需要处理 `lib/nanobot` 子模块或提供测试 fallback。

严禁做：

- 严禁 CI 依赖真实 API key。
- 严禁 CI 访问用户本地路径。
- 严禁上传数据库、日志、memory 文件。

验收标准：

- 新 PR 可自动运行基础检查。

预留接口：

- 后续加入 Windows/macOS/Linux matrix。

### P0-F2：安全回归测试

必须做：

- 扩展测试覆盖：
  - dangerous shell deny。
  - HITL required。
  - HITL deny。
  - HITL no provider。
  - path validation。
  - URL validation。
  - secret redaction。
- 对 `ToolPolicy` 和 `SafetyGuardrails` 增加参数化测试。

严禁做：

- 严禁测试中执行真实删除命令。
- 严禁测试中触碰真实用户目录。

验收标准：

- 高风险命令不能被确认绕过。
- 可 HITL 命令只能在安全路径和单命令场景进入确认。

预留接口：

- 后续 fuzz 测试。

### P0-F3：数据库迁移测试

必须做：

- 测试 fresh DB。
- 测试旧版本 DB。
- 测试重复迁移。
- 测试 migration 失败回滚。

严禁做：

- 严禁测试使用真实 `data/lobuddy.db`。

验收标准：

- 所有 DB 测试使用 `tmp_path`。

### P1-F4：UI smoke 测试

必须做：

- 至少覆盖：
  - TaskPanel 构造。
  - PetWindow 构造。
  - HITL dialog provider 触发。
  - Skill panel 或 memory console 构造。
- PySide6 mock 方式沿用现有测试风格。

严禁做：

- 严禁 UI 测试依赖真实显示器。
- 严禁弹出阻塞式真实对话框。

验收标准：

- headless 测试环境可跑。

### P1-F5：发布准备

必须做：

- README 修复后补充：
  - 安装。
  - 运行。
  - 测试。
  - 配置。
  - 隐私与安全说明。
- 增加 `lobuddy-health` 检查项：
  - DB 可写。
  - workspace 可写。
  - nanobot 可导入或 fallback 状态。
  - PySide6 可用。
  - 配置必要字段。

严禁做：

- 严禁在 health 中打印 API key。
- 严禁 health 自动修复用户配置。

验收标准：

- `lobuddy-health` 输出可读、可复制给开发者排查。

预留接口：

- 后续 PyInstaller/Nuitka 打包。

## 4. 建议交付切片

测试与发布是 P0，应与基础修复并行推进：

- CI 基础。
- 安全回归。
- DB migration 回归。
- UI smoke。
- health check 扩展。

## 5. 最小验收命令

```bash
ruff check .
black --check .
python -m py_compile app core ui
pytest tests/ -q
```
