# Lobuddy 5.8 系统优化计划

制定日期：2026-05-08  
目标版本：5.8.x  
交付对象：opencode  
优先级：P1

## 1. 目标

让 Lobuddy 的运行状态可观测、后台维护可控、事件流清晰、启动更轻。

## 2. 涉及模块

- `core/events/`
- `core/storage/execution_trace_repository.py`
- `core/storage/hitl_approval_repo.py`
- `core/memory/memory_maintenance.py`
- `core/skills/skill_maintenance.py`
- `app/`
- `ui/`
- `tests/`

## 3. 任务优先级

### P1-B1：统一运行事件模型

必须做：

- 定义统一事件类型：
  - task queued/started/completed/failed
  - tool call planned/executed/blocked
  - HITL requested/approved/denied/timeout
  - memory proposed/accepted/rejected
  - skill candidate created/approved/disabled
  - pet exp gained/level up/ability unlocked
- 保留现有 Qt Signal，但新增事件发布路径。
- 事件 payload 必须可安全记录、可测试、尽量可序列化。

严禁做：

- 严禁移除现有 Signal。
- 严禁把 UI 对象塞进 core event payload。
- 严禁 event payload 携带完整 secret、API key、长工具输出。

验收标准：

- EventBus 可以订阅并收到 task/HITL/memory 的最小事件。
- 测试验证事件 payload 不含敏感字段。

预留接口：

- 后续开发者面板、任务时间线、自动化统计都从该事件模型读取。

### P1-B2：维护调度器

必须做：

- 新增 `core/services/maintenance_scheduler.py` 或同等模块。
- 支持注册维护任务：
  - memory cleanup。
  - skill stale review。
  - execution trace cleanup。
  - asset cache cleanup。
- 维护任务必须可配置开关和间隔。
- UI 启动后延迟执行，不阻塞首屏。

严禁做：

- 严禁在 UI 主线程执行重维护任务。
- 严禁维护任务删除用户数据，除非已有明确过期/归档策略。
- 严禁吞掉所有异常后无日志。

验收标准：

- 可以在测试中用 fake clock 或短间隔触发维护任务。
- 维护任务失败不影响主程序。

预留接口：

- 后续接入维护日志面板。

### P1-B3：开发者/高级用户可观测性面板

必须做：

- 新增只读面板或只读 service，优先展示：
  - 最近任务耗时与状态。
  - 最近工具调用摘要。
  - HITL 决策记录。
  - token 使用概览。
  - 最近错误。
- 从 repository 或 event store 读取，不直接读日志文件。

严禁做：

- 严禁展示完整 API key、bearer token、邮箱等敏感数据。
- 严禁展示完整大模型 prompt。
- 严禁在面板中提供危险命令重放按钮。

验收标准：

- 有最小 UI 或 data provider 测试。
- 打开面板不影响任务执行。

预留接口：

- `core/services/observability_service.py`
- 后续可导出诊断包。

### P1-B4：启动性能与懒加载

必须做：

- 延迟加载非首屏能力：
  - memory control console。
  - skill lab。
  - history window。
  - theme editor。
  - observability panel。
- 图片/GIF/主题色提取保持缓存，但缓存要有上限和清理策略。

严禁做：

- 严禁为了懒加载破坏设置读取。
- 严禁让用户第一次点击功能时无反馈卡死。

验收标准：

- 启动路径无明显新增阻塞。
- 懒加载模块第一次打开有错误处理。

预留接口：

- 后续可加 startup profiler。
