# Lobuddy 5.8 记忆系统进化计划

制定日期：2026-05-08  
目标版本：5.8.x  
交付对象：opencode  
优先级：P1

## 1. 目标

从“系统自动记住”进化为“用户可查看、可确认、可删除、可追溯、可暂停”的记忆系统。

## 2. 涉及模块

- `core/memory/`
- `core/storage/chat_repo.py`
- `core/storage/db.py`
- `ui/`
- `app/`
- `tests/test_memory_*.py`

## 3. 任务优先级

### P1-C1：记忆控制台 MVP

必须做：

- 新增记忆控制台 UI 或服务层 MVP。
- 支持查看：
  - user profile。
  - system profile。
  - project memory。
  - episodic memory。
  - procedural memory。
- 支持操作：
  - delete。
  - deprecate。
  - edit content。
  - view source/provenance。
- 所有写操作必须走 MemoryService 或 MemoryWriteGateway 规定边界。

严禁做：

- 严禁 UI 直接写 SQLite。
- 严禁绕过脱敏保存。
- 严禁默认展示完整敏感内容。

验收标准：

- 测试覆盖 list/deprecate/delete/edit。
- UI 操作后 projection 同步刷新。

预留接口：

- `core/memory/memory_control_service.py`
- 后续可接记忆确认队列。

### P1-C2：记忆来源追踪展示

必须做：

- 在 MemoryItem 展示层显示：
  - source。
  - source_session_id。
  - source_message_id。
  - created_at / updated_at。
  - confidence / importance。
- 如果缺少历史 provenance，显示“历史数据，无精确来源”。

严禁做：

- 严禁为了展示来源去反向猜测 message_id。
- 严禁将 source_session_id 当作用户可见敏感信息直接暴露在普通模式；普通 UI 可显示摘要，高级模式显示完整 ID。

验收标准：

- 新写入 identity/preference memory 可查看来源。
- 旧数据不报错。

预留接口：

- 后续点击来源跳转会话历史。

### P1-C3：记忆冲突确认

必须做：

- 当新记忆与已有 active 记忆冲突时，不直接覆盖。
- 新增 pending/conflict 状态或 conflict candidate 表。
- 用户确认后再 update/deprecate 旧记忆。

严禁做：

- 严禁用简单字符串包含关系判断所有冲突。
- 严禁 silent overwrite 用户身份、偏好、项目路径等高价值记忆。

验收标准：

- 测试覆盖同一 identity key 不同 value 的冲突。
- UI 或服务能列出待确认冲突。

预留接口：

- `MemoryConflictResolver`
- 后续可引入 LLM 辅助解释冲突，但最终由用户确认。

### P1-C4：隐私模式与临时会话

必须做：

- 新增会话级开关：
  - 不写长期记忆。
  - 不参与 exit analysis。
  - 不注入历史记忆。
- UI 有明确状态提示。

严禁做：

- 严禁隐私模式下仍写入 structured memory。
- 严禁隐私模式下把对话内容写入 skill candidate。

验收标准：

- 隐私会话完成后 memory 表无新增业务记忆。
- 普通 chat history 是否保存需按现有策略明确，不得含糊。

预留接口：

- 后续可扩展为项目级隐私策略。

### P2-C5：冷历史自动召回预留

必须做：

- 只预留接口，不在 5.8 做复杂 RAG。
- 明确 session_search 仍是受预算约束的 cold recall。

严禁做：

- 严禁全量向量化历史。
- 严禁自动把大量历史塞入 prompt。
- 严禁全盘文件索引。

预留接口：

- `RecallPolicy`
- `RecallBudget`
- `SessionRecallCandidate`

## 4. 跨模块边界

- 业务写入统一走 `MemoryWriteGateway`。
- 用户手动管理可通过 `MemoryControlService` 调用 `MemoryService`，但不得直接写 repo。
- 所有写入必须脱敏。
- provenance 字段必须延续。
