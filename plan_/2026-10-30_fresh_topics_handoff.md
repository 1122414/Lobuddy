# C2：让新鲜事进入主动陪伴

状态：实施前核对；没有实现或完成声明。承接 [总计划](2026-10-28_companion_product_evolution.md) 与 C1。用户确认的第一批兴趣为 AI 陪伴、开源项目与创作工具；同时需要续接近况和分享相关新内容。B2 的事实质量问题仍是独立未决项。

## 可验证结果

她从用户明确选择的公共项目中找到一条仍新鲜的发布，与可续接的近况比较后选择是否说一句；用户能查看原文和发布时间，也能点开接着聊。关闭/更换来源、发布过期或正文变化后，旧话题不能继续展示、重放或注入后续上下文。没有合适内容时保持安静。

## 当前代码已确认的复用点

- `CompanionDialogue.material/source` 当前仅识别项目来源与个人记忆，需要显式增加公开发布来源身份；不能把新闻套进个人经历分支。
- `InvitationPlanner.candidates/prepare/choose` 已有候选比较、来源修订、时机/预算和发送前检查。公共来源复用同一流程，不能再建一个不受日额度约束的主动循环。
- `CompanionHandoffs.current/reconcile/context` 按来源与修订检查接话；撤销会处理派生消息、摘要和持久引擎关联。公共来源需要接入这些检查，不能仅隐藏设置卡片。
- 待处理邀请的 key 当前依赖相处来源 epoch，公共缓存变化尚不会让一次旧的 `no_valid_sources` 决策失效。接入时必须验证新发布到达、相同内容重读、条目过期三种情况；读取时间不能单独成为内容修订。
- C1 的兴趣是配置，公开发布是有界缓存，两者尚未成为记忆或聊天事实。C2 也不默认把它们写入 MemoryWriteGateway。

## 实施次序

1. 增加公开发布的内部来源标识、稳定内容修订与有效性读取；来源文字包含项目、标题、发布时间和有界正文。保持 C1 网络边界和默认关闭行为。
2. 把新来源加入有界候选比较，显式传入用户选择的兴趣和公开发布身份；保留近况的候选机会，不以列表顺序或强制一半一半代替选择。沿用两次分析和已有输入/输出上限。
3. 在配置、缓存变化和到期时重新校验准备中/待展示/已接续的内容。配置撤销应终止旧的后台分析；晚到模型结果不能恢复旧来源。
4. 补充来源展示里的原文和日期，再执行固定正反例、真实发布与隔离原生接话。明确区分模型组件、离线预置事件、原生 UI 和真实 macOS 返回事件证据。
