# Jev 提示时机使用说明

Jev 已接入源码中的后台任务结果通知。DSH 继续负责对话和执行；Jev 判断任务结果与委托是否相关、是否明确需要立即行动、是否重复，代码据此决定是否弹气泡。

## 开启

1. 设置 → 服务凭据 → TypeSafe Jev，输入 API Key，保存到 macOS 钥匙串后重启。开发时也支持本机 `.env` 的 `TYPESAFE_API_KEY`；不要提交此文件。
2. 设置 → 什么时候告诉你，选择「仅观察，不改变提示」。默认是关闭。
3. 到通知收件箱展开「Jev 提示判断」，查看建议、三个判断的置信度、实际模型版本、耗时和 token 用量。确认适合自己的习惯后切换「参与提示时机判断」。

模式切换立即生效。关闭停止在途判断并恢复原投递规则；配置新凭据需要重启。
本次没有自动改动个人数据库或 `.env` 的模式，没有更新 10.19 的旧安装包；开发运行使用最新构建。

## 三种结果

- **立即提示**：与委托相关、有明确十分钟内截止时间或立即行动要求、不是重复内容，而且判断置信度达到门槛。仍遵守专注、免打扰、正在输入/对话/语音及安静边界。
- **延后合并**：普通完成结果，或判断不确定/请求失败/预算耗尽。最早十分钟后允许展示，届时仍检查硬规则；期间可直接打开收件箱。
- **仅留收件箱**：高置信度确认内容重复或与委托无关。不标记已读，不丢弃结果。

明确设定的时间/事件提醒沿用原规则，不交给 Jev 决定。当前没有使用 Jev 控制工具权限、记忆写入、模型路由或工作流晋升。

## 数据与预算

启用后会发送：最长 600 字符的任务结果、最长 600 字符的对应委托目标，以及同一委托最近一天最多三条已投递结果（每条最多 300 字符）。不跨委托借用历史，不发送完整聊天、文件正文或录音。现有敏感信息/密钥检测命中时不发请求；检测不是对任意敏感表达的完整识别保证。原通知仍可在收件箱查看。

只有固定 `https://api.typesafe.ai/v1/systemone` 可接收请求，不跟随重定向；每次最多四秒，无自动重试。默认 `jev-1.13.0`（明确版本，避免别名漂移）。默认置信度门槛 0.75；Choice 置信度是概率分布的统计量，不是该判断必然正确的概率。

独立预算默认为每日 30 次、60000 请求正文 UTF-8 字节，按上海日期结算，调用前持久预留；失败和进程中断不退还预留。它不与主模型后台学习预算混为一谈，也不是 TypeSafe 计费 token。实际 API token 在判断记录中显示，未知就显示未知。

可通过 `.env` 或校验后的 `settings.patch` 配置：
`JEV_MODE`、`JEV_MODEL`、`JEV_MIN_CONFIDENCE`、`JEV_DAILY_CALLS`、`JEV_DAILY_REQUEST_BYTES`。
每条通知至多请求一次；改变阈值/模型不重新判断旧通知，观察模式结果不会追溯成为投递决定。

## 验证边界

真实 API 的六个开发样例和四个附加样例最终均通过；两次早期失败报告保留。样例都是合成数据，不能据此声称日常准确率、节省成本或优于主模型。中文表达仍需要实际观察。
