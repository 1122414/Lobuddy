# Lobuddy 全项目审查与升级报告

审查日期：2026-07-19

## 1. 产品结论

Lobuddy 已从“能聊天的桌宠”升级为具备以下闭环的主动陪伴型桌面 Agent：

1. 在用户明确开启后，本地观察空闲时长、活跃应用、连续工作和任务失败信号；
   情绪与陪伴需要只来自用户主动提交的限时 Check-in，不从桌面活动猜测。
2. 以静默时段、每日上限、最小间隔、专注模式和“先安静陪着”控制主动关怀，
   避免把陪伴做成打扰。
3. 通过 nanobot 执行复杂任务，并把工具调用置于统一的预算、安全和追踪边界内。
4. Computer Use 采用“计划—观察—授权—执行—校验—恢复”的持久化状态机。
5. 图片进入视觉模型前必须通过路径、大小、扩展名、魔数和 MIME 一致性校验。
6. 用户可以主动框选屏幕区域提问；选区不进入聊天与长期记忆，在任务结束、
   移除、过期或退出时删除，也不会隐式授予电脑操作权限。
7. 成功工作流只能生成脱敏、待审阅的技能候选；自动进化候选还必须独立核验
   来源 Task Run、成功结果与已完成工具轨迹。批准前必须通过与内容哈希绑定的
   隔离包评测和人工确认，不允许静默自我修改或自动启用。
8. 对话、结构化记忆、技能、任务、审批与执行轨迹均有本地持久化和隐私边界。
9. 记忆可解释来源和用途，用户能确认、校正、停用、恢复或永久遗忘，
   每次关系变化都形成不保留遗忘正文的修订记录。
10. 通过 Codex 标准宠物协议联动本机 `~/.codex/pets` 与 codex-pets.net 社区，
   伙伴外观会随 Agent 工作状态同步变化。
11. 每次复杂工作形成持久化 Task Run：记录脱敏工作阶段、显式依赖、
    当前关键路径、预计与实际耗时、模型用量证据、重启安全暂停和不可变重试谱系，
    并在任务卡和“工作记录”中向用户解释。
12. 每次任务只召回与当前请求有词面依据、仍处于有效状态且作用域匹配的记忆；
    所有分区共享硬预算，命令中心只显示类型与数量；用户可按 Task Run 查看并反馈
    实际使用的结构化记忆，不需要暴露本次提问或回答。

当前实现已经具备可用的产品骨架和可靠的安全底座。它的核心差异不是“多一个聊天窗口”，而是将陪伴、任务执行、电脑操作和能力进化放进同一个可解释、可暂停、可恢复、可审计的系统。

## 3. 本轮关键升级

### 稳定性与安全

- 修复运行时维护装配、技能文件生命周期、敏感记忆边界和退出链路。
- 数据库设置覆盖不再依赖未初始化的全局实例，首次启动也不会提前创建空数据库。
- 安全护栏是不可由旧配置关闭的运行时不变量。

### 主动陪伴

- 新增本地观察采样、陪伴事件仓库、干预策略和运行时。
- 支持工作过久、离开后返回、深夜、连续失败等关怀场景。
- 支持静默时段、最小间隔、每日打扰上限和专注状态抑制。
- 每次关怀展示“为什么现在”，并支持“有帮助 / 稍后 / 不再提醒此类”。
- 显式反馈会形成场景级偏好：可暂时停止全部关怀，也可只静音特定类型。
- 反馈仓库只保存提醒类型、动作和时间；设置页可查看摘要并重置静默偏好。
- 桌宠快捷入口新增 Companion Check-in：用户主动选择当前心情、精力与需要的支持；
  不收集自由文本，也不会把打开的应用解释成情绪。
- Check-in 只保留最新一条并自动过期，可在同一面板立即清除；隐私模式仅驻留内存。
- “先安静陪着”直接抑制主动关怀，“陪我专注”接入现有专注计时，
  低能量状态只在用户明确提交后调整休息与失败支持语气。

### Computer Use

- 新增可恢复的计划、步骤、快照、审批和授权模型。
- 工具调用经过统一代理、风险检查、调用预算和执行追踪。
- 高影响动作必须逐次确认；未授权、过期、越界或状态不一致时拒绝执行。
- 原生 Win32 控件元数据会与截图视觉目标临时融合，输入框内容不会被控件探测读取。
- 每个动作必须绑定未过期的观察、语义目标和预先声明的可见结果。
- 未验证动作不能继续，最新动作未验证不能宣告成功；连续两次验证不明确会安全停止。
- 检查点持久化目标、证据来源、预期结果和验证次数，但不保存截图或输入文本。

### UI 与陪伴感

- 使用原创月亮猫形象作为默认桌宠，同时保留用户自定义形象优先级。
- 重构桌宠状态胶囊、快捷操作、对话命令中心、能力入口、任务卡和设置布局。
- 任务卡实时展示 Computer Use 的计划、授权、观察、动作与验证状态，
  同时展示 Task Run 的尝试次数、工作阶段完成数、等待原因、当前关键路径、
  步骤耗时、整体进度、已用时间与预计剩余时间。
- 新增面向用户的“工作记录”：使用真实 Task Run、工具轨迹、人工确认与
  Token 计量生成完成率、耗时、暂停和工具可靠性，不制造推测指标。
- 新增 Codex Desktop、本机自定义宠物与 codex-pets.net 在线社区入口，可搜索、
  分页、预览、安全领养并立即切换。
- 可从正在运行的 Codex Desktop 自动定位受限 `app.asar`，读取 9 只内置伙伴并生成
  本机兼容缓存；不会修改 Codex 安装或把官方素材提交到仓库，发现过程在后台线程执行。
- 桌宠快捷菜单与右键菜单可直接进入在线伙伴库；当前使用 Codex 宠物时会显示
  伙伴名称，换装完成后立即刷新桌宠并给出陪伴反馈。
- Codex 标准 8×9 图集会完整转换为待机、左右移动、挥手、跳跃、失败、等待、
  执行和审阅动作；任务成功使用跳跃庆祝，点击使用挥手，成长反馈使用跳跃，
  且临时动作结束后恢复真实任务状态。
- 新增确定性的离屏渲染脚本，可生成核心窗口预览用于视觉回归。

### Task Run 工作执行闭环

- 每次用户请求对应一个持久化 Task Run，并按顺序记录排队、开始、进展、
  完成、失败、安全暂停与重试事件。
- 入队与唯一 worker 预约在同一把异步锁内完成，消除 worker 退出瞬间入队却
  无人接手的 lost-wakeup；并发入队不会创建相互竞争的执行 worker。
- 每个已接纳 Task Run 都会得到终态。清空队列或应用退出时，正在执行和仍在
  等待的任务都会持久化为“已安全暂停”，不会静默丢弃，也不会伪装成执行失败。
- Executor 结果必须属于当前 Task Run；跨 Run 结果会在持久化前被收敛为当前
  Run 的受控失败，不能污染另一条任务记录。
- 安全暂停不会触发失败型陪伴干预或错误表情；任务卡使用独立的“已安全暂停”
  状态，并继续通过 freshness-bound Recovery Review 提供显式重试。
- 每个带稳定 key 的进展会投影为 Work Stage；依赖只能引用同一 Task Run 中
  已出现的阶段且不可改写，未满足依赖的阶段不能进入执行或成功状态。
- Computer Use 的计划、授权、观察、动作、验证和收尾形成显式依赖链；
  任务卡只展示当前已知图的关键路径，不把它当作执行授权。
- nanobot 工具通过 Adapter 在真实 `execute` 边界计时；持久化内容只有工具类型、
  成败和耗时，不包含参数、命令、文件内容或原始结果。
- 进展只保存经过长度限制和凭据、邮箱脱敏的摘要，不保存完整提示词或图片。
- 整体与阶段时长预测使用历史完成记录的加权中位数；没有历史时使用任务难度
  或阶段族基线，且不会超过任务超时。
- 每个 Task Run 保存不含正文的 Model Usage Evidence：优先采用服务商返回的
  prompt、completion 与 cached token；本地计算始终标注为估算，未知来源不伪装成实测 0。
- Token 参考预算只在同模型、同难度至少有 3 条成功样本后生成；cached token
  已包含在 prompt token 中，不会重复计数，工具结果也不会额外叠加。
- 未配置显式、带版本的价格源时不展示货币成本，避免仅凭模型名猜测账单。
- 应用重启后，遗留的排队或运行任务会安全暂停，不会自动重放可能产生
  重复副作用的电脑操作。
- 重试必须由用户明确触发，会创建不可变的新尝试并链接旧尝试；同一失败
  尝试只能生成一个直接重试，图片任务需要重新选择图片。

### 可解释的关系记忆

- 将原来的数据库式“记忆控制台”重构为关系档案，直接说明为什么记住、
  可信程度以及是否会在后续对话中使用。
- 用户可确认准确、保存校正、暂时停用、恢复使用或永久遗忘；
  修订原因与操作主体进入按时间排序的关系时间线。
- 记忆修订只保存内容哈希与最小原因。永久遗忘会同步删除 SQLite 正文以及
  `USER.md`、`SYSTEM.md`、`PROJECT.md`、工作区 `MEMORY.md` 中的投影内容。
- 冲突裁决把两侧状态、候选状态和修订放在同一事务中；自动裁决只允许
  明显更高置信度的事实胜出，较弱新信息不会覆盖更强的已确认事实。
- 记忆搜索覆盖正在使用、等待确认和已停用状态，用户可找回并恢复旧记忆。
- 记忆控制台提供本地 JSON 迁移包。导出仅包含偏好、项目约定、共同经历和
  协作方法，不携带聊天、来源会话、消息 ID、Task Run、屏幕像素或使用时间。
- 导入把迁移包当作不可信数据：限制 2 MB / 500 条，校验版本、包校验和与条目
  指纹，预览后再次检查文件摘要；全部生成新 ID 并进入“等待确认”，隐私模式拒绝写入。
- 导入记录与记忆修订在一个事务中完成；重复内容按稳定指纹跳过，整批任一修订
  写入失败则全部回滚。只有用户逐条确认后，导入内容才可能进入后续召回。
- 统一写入网关对“高重要性但低置信度”的 AI 提案不再只返回临时对象，而是
  原子保存为等待确认的结构化记忆，使控制台的审查入口与真实写入链路一致。

### 有依据的任务记忆召回

- 短问题拥有可配置的最低有效召回空间，但始终服从单次任务记忆总预算。
- 情景记忆与流程记忆必须命中当前请求关键词并达到相关阈值；无关、过期、
  已停用或其他会话作用域的记忆不会进入提示词。
- 用户档案、助手设定、项目上下文、会话摘要与历史召回共用一个硬预算，
  入选项会更新最近使用时间，但不会伪装成刚刚编辑。
- 修复 nanobot 前缀 session key 与 Lobuddy 原始会话 ID 不一致造成的隐私边界风险；
  隐私模式同时阻断强信号写入与历史召回。
- 命令中心显示“记忆 · N”“隐私 · 0”或“记忆关闭”，提示只包含类型与数量；
  Task Run 也只保留“参考 N 条已确认记忆”的脱敏进展。
- 每条实际参与 Task Run 的结构化记忆生成幂等 Memory Recall Receipt，只保存
  Task Run / session / memory ID、类型、最小调用原因、字符数、时间和显式反馈；
  不保存本次提问、回答、记忆正文、工具结果或屏幕证据。
- 用户可从“记忆 · N”打开本次反馈面板。“有帮助”和“这次不相关”只留下
  一次性证据，不改写内容、置信度或状态；“内容不对”会在同一事务中记录反馈、
  暂停该记忆并追加修订，等待用户校正或重新确认。
- Receipt 绑定不含正文的记忆版本时间戳；若记忆在 Task Run 后已更新，旧记录仍可
  查看，但不能再评价或改变新版本。
- 记忆档案会显示累计用于回答、有帮助、不相关和内容不对次数，帮助用户发现
  陈旧或误用记忆，但不会把一次反馈伪装成全局奖励分数。

### 多模态与能力进化

- 图片选择后先验证再预览，图片-only 任务会补齐清晰的默认提问。
- 命令中心新增“选区”入口：先冻结当前显示器，再由用户拖拽并确认唯一可见区域。
- 选区通过魔数、格式、解码尺寸和像素预算校验后进入受限临时目录；
  未发送选区会过期，任务完成、失败、移除、替换或退出都会删除。
- 选区像素不进入聊天气泡、聊天数据库或结构化记忆；该入口只提供视觉上下文，
  不复用 Computer Use 全屏观察，也不授予鼠标或键盘动作权限。
- 将高质量成功工作流转成待审技能候选，过滤私密会话、图片任务和 Computer Use 等高风险来源。
- 候选内容经过凭据、邮箱、卡号、用户目录等敏感信息清洗，并执行结构与危险命令校验。
- 自动进化候选先仅进入待审队列；Task Run 成功结果持久化后，来源证明模块会
  独立比对来源任务、会话绑定、成功结果、候选声明工具和已完成工具轨迹。
- 来源证明只保留 Task Run ID、状态、工具名与缺失项，不读取或复制提示词、
  命令参数、文件路径、屏幕像素和模型原始输出。
- 每个候选会在临时目录完成不执行命令、不联网的隔离包投影，并运行结构、
  包身份、触发条件、流程可操作性、隐私、来源证明、权限和投影完整性八类固定检查。
- 评测报告与提案内容哈希绑定，旧报告不能批准修改后的内容；生成置信度不能
  替代评测，也不能绕过人工审批。
- 能力实验室展示评测分数、逐项结论、权限画像，以及“来源已核验/待核验”和
  观测到的工具名；来源未核验的自动候选不能批准。
- 批准采用“临时投影—数据库事务—原子发布”；数据库或文件发布失败都会补偿
  回滚，未审能力不会因崩溃窗口留下可加载的 `SKILL.md`。
- SkillManager 只允许访问 `workspace/skills/<合法名称>/SKILL.md`，拒绝数据库路径
  篡改、符号链接和非托管同名文件覆盖。

## 4. 能力边界

- “主动观察”目前是低侵入的桌面活动描述，不使用摄像头、麦克风或生理传感器，
  也不会宣称识别用户真实情绪。只有用户主动提交的限时 Check-in 可以携带心情与支持意图。
- Computer Use 的安全状态机已经完成，但能否稳定操作所有第三方软件仍取决于窗口结构、分辨率、权限和定位能力。
- 复杂任务质量依赖所配置模型、API 可用性、工具权限和任务描述质量。
- Task Run 已支持重启后的安全暂停和新尝试，但尚未承诺从任意工具步骤原地续跑；
  需要连续执行时，用户应在查看旧尝试后明确创建新的重试。
- 能力进化是“生成并审阅技能提案”，不是允许 Agent 自行修改核心代码或绕过用户授权。
- 当前 Skill Evaluation 是不执行候选指令的包与策略门禁，不等同于运行任意命令
  的系统沙箱；后续行为回归应使用受限模拟工具，而不是直接放开 Shell 或网络。
- 本地聊天与业务数据默认保存在 SQLite；调用外部模型时，用户提交的任务内容仍会按所选服务商协议发送。
- 在线宠物目录仅在用户打开社区页时读取；领养只下载 codex-pets.net 固定 HTTPS
  资源路径，经过 URL、响应大小、图片魔数、MIME 和图集尺寸校验后原子安装。
